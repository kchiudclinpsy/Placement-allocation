# Placement Allocation Toolkit

This toolkit validates two Microsoft Forms exports and produces a recommended allocation plus alternative options.

## Files

- `students.csv`: student preferences and constraints.
- `placements.csv`: placement availability and requirements.
- `placement_preferences.csv`: placement-provider rankings of students.
- `allocation_rules.csv`: adjustable score weights; weights must total 100.
- `allocate.py`: validation and optimization script.
- `requirements.txt`: Python dependencies.

## Important data convention

Student preference fields use `placement_id` values, not specialty names. This avoids ambiguity when multiple sites share a specialty. Keep IDs unique and stable.

## Microsoft Forms workflow

1. Create a student Form with questions matching the `students.csv` headers.
2. Create a placement Form matching `placements.csv`. Placement rankings can be collected in a separate Form and reshaped to the three-column `placement_preferences.csv` format.
3. Export responses to Excel, then save each required worksheet as CSV UTF-8.
4. Rename columns exactly as shown in the templates. Remove the Forms metadata columns or leave them outside these CSV files.

## Setup

Requires Python 3.10 or later.

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

On macOS/Linux, activate with `source .venv/bin/activate`.

## Run the included simulation

From this folder:

```bash
python allocate.py --input-dir . --output-dir outputs --options 3
```

Outputs:

- `outputs/validation_report.csv`
- `outputs/allocation_results.csv` (recommended option)
- `outputs/allocation_options.csv` (up to three alternatives)
- `outputs/allocation_summary.csv`

The included sample has six students and six placement slots.

## Validation rules

### Blocking errors

- Required columns must exist.
- `student_id` and `placement_id` must be unique.
- All four student preferences are required, distinct, and valid placement IDs.
- `max_travel_minutes` must be a positive integer.
- `car_owner` and `requires_car` must be `Yes` or `No`.
- Placement capacity must be a positive integer.
- Placement preference references must exist; each placement/student pair and each rank within a placement must be unique.
- Rule weights must be numeric, between 0 and 100, contain the four expected criteria, and total 100.
- Total placement capacity must be at least the number of students.

### Hard allocation constraints

- Each student is allocated exactly once.
- Placement capacity is not exceeded.
- A car-required placement only accepts a student with `car_owner=Yes`.
- `required_specialty`, when supplied, must match.
- The placement's `minimum_travel_minutes` must not exceed the student's maximum.

### Soft scoring criteria

- Student preference: ranks 1 to 4 score 100, 75, 50, and 25.
- Placement preference: ranked candidates receive a declining score; unranked candidates score zero.
- Fairness adjustment: sample implementation gives 100 where a special-circumstances flag is present and 50 otherwise.
- Travel fit: rewards spare travel-time capacity within the student's limit.

Change weights in `allocation_rules.csv`, not in Python. Review the fairness formula and governance policy before operational use.

## Interpreting alternatives

Option 1 is the highest-scoring feasible allocation. Each later option is generated by excluding one low-scoring pair from the previous solution and optimizing again. Alternatives are decision-support options, not randomized outcomes.

## Governance and data protection

- Use pseudonymous student IDs in working files where possible.
- Avoid putting detailed health or disability information in CSVs; use a minimal review flag and keep supporting information in a restricted system.
- Record the approved rules and weights before reviewing outcomes.
- Maintain a human review stage for reasonable adjustments, exceptional circumstances, and infeasible cases.
- Retain the input files, validation report, rules, selected option, decision rationale, and script version as an audit trail.
- Do not use protected-characteristic data to rank students unless there is a documented, lawful, proportionate policy and appropriate oversight.

## Adapting the templates

You may add descriptive columns, but do not rename or remove required columns without updating `allocate.py`. For more than four preferences, add columns and extend `PREF_COLS` and the scoring map in the script.

## Visual summary

After running the allocator, create the self-contained dashboard:

```bash
python generate_visual_summary.py --output-dir outputs
```

Open `outputs/visual_summary.html` in Microsoft Edge, Google Chrome, or another modern browser. It includes:

- validation status and headline outcomes;
- preference and placement-utilisation bars;
- an interactive selector for the recommended and alternative options;
- a concise description of what the toolkit validates and optimizes;
- a print-friendly layout for saving to PDF.

The dashboard contains no external scripts, fonts, or network calls. It can therefore be retained with the run's CSV audit files. The visual summary is decision support, not an automatic approval record; a human reviewer should document the final selection and any exceptional-circumstances decision.
